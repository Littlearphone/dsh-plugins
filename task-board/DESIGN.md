# 任务板 · 交互设计

一条任务从"用户脑子里冒出来"到"实现完成"的全部分支。写代码前以本文为准。

**两条前提，全文都建立在它们上面：**

1. 任务之间可能毫不相关。
2. 轨道不是线性流程：可以跳级、可以来回。

因此不存在"上一步"。回滚、检查点、迁移都以**这张卡自己的执行记录**为单位。

## 1. 概念

| 概念 | 定义 |
|---|---|
| 任务卡 | 标题、描述、轨道、标记、锁定会话、执行记录 |
| 轨道 | 待办 / 设计中 / 待实现 / 实现中 / 待验收 / 已完成。**迁移表才是真源** |
| 标记 | 要不要人出手：等你批 / 等你验 / 阻塞。与轨道正交 |
| 锁定会话 | 首次派单选定；重开（fork）时改锁 |
| 执行记录 | 每次派单一条：`runId, sessionId, baseline, end, requestId/itemId, 结果` |
| 检查点 | 执行记录里的两个快照，命名 `t7#3`。不是"阶段" |

**没有"已暂停"状态**：跑完一轮但没报告的卡就停在原阶段，主动作变成「继续」。

## 2. 派单消息：对话包装

任务可能与会话里之前的对话毫无关系，所以不能把任务正文直接一发。每条派单消息固定六段：

```
【任务 t7f3a · 阶段：实现】
标题：任务板数据模型
────────────────────────
背景：<只放本任务需要的最小上下文：相关文件、已确认的方案要点>
要求：<做什么、做到什么算完>
边界：<只能改哪些路径；明确不做什么>
────────────────────────
这是一条独立任务，与本次会话更早的对话无关。此前讨论的任务、结论、未完成的改动都不属于
本任务。若发现工作区有其它任务的残留改动，不要顺手修改，在报告里列出来即可。
先给出 3 步以内的计划，再动手。
完成后调用 task_board_report(taskId:'t7f3a', outcome:'implemented', note:'…')。
```

六段：身份头 / 背景 / 要求 / 边界 / 隔离声明 / 输出契约。

**解决什么**：任务信息自包含（不依赖会话历史）；显式声明与之前无关；要求先自查工作区残留且
只报告不修改；固定报告契约。

**不解决什么**：这是软约束。会话历史里若有"用户明确要求"的内容，模型仍可能参考。

**硬边界只有一种**：任务独占会话（§2.1）。

### 2.1 两种绑定策略

| | 复用会话（默认） | 独占会话 |
|---|---|---|
| 派单目标 | 当前 / 新建 / 工作区已有会话 | 只能用本任务自己的会话 |
| 上下文 | 带包装，尽力隔离 | 天然零串味 |
| 排队 | 跨任务共用一个 FIFO | 只有本任务自己的多次执行会排 |
| 代价 | 串味风险 | 每个任务付一次"重新认识项目"的成本、会话数膨胀、跨任务知识不传递 |

绑定策略**不是用户开关**，是实现的取舍：先把包装做到位，默认复用会话；实测仍串味就整站切到
独占，一次决定。不做每张卡的开关——那等于把判断推给用户。

## 3. 版本控制

### 3.1 粒度：一次派单，一个基线

派单前打 `baseline`，本轮结束打 `end`。回滚单位是**执行记录**，不是阶段。可回滚点就是这张卡
的执行记录列表，按时间排，标注那次跑出了什么。

### 3.2 回滚按路径，不做整树 reset

工作区共享、任务无关，所以只撤这张卡那次执行碰过的路径：

```
baseline..end 的 diff
  修改 / 删除 → 从 baseline 取回
  新增       → 删除
  其它任务之后动过同一路径 → 冲突：不覆盖，列出来让人决定
```

回滚前先打 WIP 快照，永远能再回去。确认条写清"恢复 N 个、删除 M 个新增、冲突 K 个"。

**冲突不跳过、不禁止，弹确认**：逐条列出「文件 · 谁改的 · 保留哪边」，默认保留当前内容
（不覆盖），用户可逐个改成"回滚到我的版本"。

### 3.3 快照方案：影子仓库

```
git --git-dir=$DSH_HOME/task-board/repos/<ws-key>.git --work-tree=<工作区>
```

不碰用户 `.git`（index、refs、worktree 全不动），对象与 ref 都在 DSH 目录。忽略规则沿用工作区
`.gitignore`，另加 DSH 管理的 `core.excludesFile` 兜底。每次快照有超时与体积上限，超限放弃
本次快照并标注，不阻塞任务。

### 3.4 没有 git：警告 + 可选初始化，一切要确认

派单时 `git rev-parse --absolute-git-dir` 检测一次。

| 情形 | 行为 |
|---|---|
| 仓库内 | 快照可用 |
| 不在仓库内 / 找不到 git | 卡片灰锁「无版本控制」，确认面板警告"中断后无法回滚"；同时给一个**明确的**「初始化仓库」入口 |

「初始化仓库」的交互（**任何一步都不许静默**）：

```
将在这个目录执行：
  git init
  git add -A && git commit -m "task-board: initial snapshot"
  （可选）写入 .gitignore，内容如下：<预览>
[取消] [执行]
```

- 按钮只在用户主动点开任务板设置或点灰锁时出现，不弹窗打断。
- 执行前展示完整命令与将创建的文件；用户逐项确认。
- 用户拒绝 → 本工作区保持降级，不再询问（除非手动再来）。
- 插件不做任何未经确认的写操作：不自动 `git init`、不自动写 `.gitignore`、不动 git 配置。

降级模式：不能回滚、没有变更对比。重开文案必须写"工作区可能有上次的残留，先自己核对"。

## 4. 动作：统一成"离开"

拖动、停止、删除是同一件事：**把卡挪到别处**。

```
move(card, target?):
  1. 若在运行/排队 → 弹去向选择器（target 未定时必须选，不能空着落）
  2. 用户确认后才产生副作用：cancel() / 撤本卡未消费条目 / 可选回滚 / 改轨道或删卡
  3. 用户取消 → 什么都不发生，任务继续跑，队列不动
```

**确认在前，副作用在后。取消 = 零效果。**

去向来源：

| 触发 | target |
|---|---|
| 拖动松手 | 目标轨道（预填） |
| 点「停止」 | 未预填，必须选一个合法轨道 |
| 点「删除」 | 删除 |

停止的去向**没有默认高亮**，也不预先渲染任何东西：点了才会出现选择器，选完才生效。停止后
卡落到你选的那条轨道，进度由会话和执行记录保留，不靠卡片状态。

### 运行态

同一条轨道里的卡可能处于完全不同的状态，静态样式分不出来，必须把动效算进去：

| 状态 | 判定 | 视觉 |
|---|---|---|
| 排队中 | 账本里有本卡未消费的投递 | 静态灰点 + 「排队第 N」 |
| 运行中 | 账本当前执行条目 = running | **脉冲动效** + 用时（秒级跳动） |
| 等你回答 | 会话 running 且有待审批/待回答 | 琥珀实心点（不动）+ 「等你回答」 |
| 空闲 | 无排队、不在执行 | 静态空心点 |
| 报错 | `lastAgentError` | 红色三角 + 悬停显示 |
| 已归档 | 会话不可用 | 灰锁 |

两个容易错的地方：

- `AgentStatus` 只有 `idle` / `running`，**等待审批也算 running**。所以"等你回答"必须用
  pending interaction 单独判，不能从 running 推。
- 卡片的运行态取自**账本**，不从会话状态猜：一个会话里可能挂着好几张卡，只有一张在跑，其余
  在排队。


### 动作矩阵

| 轨道 | 运行中 / 排队中 | 空闲 |
|---|---|---|
| 待办 | — | 开始设计 · 直接实现 · 继续设计 · 编辑 · 删除 |
| 设计中 | 停止 | 继续设计 · 退回待办 · 删除 |
| 待实现 | — | 开始实现 · 退回设计 · 删除 |
| 实现中 | 停止 | 继续实现 · 退回待实现 · 删除 |
| 待验收 | — | 通过 · 退回设计 · 退回实现 · 删除 |
| 已完成 | — | 重开 · 归档 · 删除 |

- 删除是通用动作，条件是不在运行/排队中。运行中删 = 停止流程里选「删除」。
- 模型到不了「已完成」，也改不了会话、撤不了队列。
- **新建会话只在 待办 / 待实现**。

### 拖动合法性

`✓` = 允许（运行中则先走停止流程）；`✗` = 不响应。

| from \ to | 待办 | 设计中 | 待实现 | 实现中 | 待验收 | 已完成 |
|---|---|---|---|---|---|---|
| 待办 | – | ✓ | ✗ | ✓ | ✗ | ✗ |
| 设计中 | ✓ | – | ✓ | ✓ | ✗ | ✗ |
| 待实现 | ✓ | ✓ | – | ✓ | ✗ | ✗ |
| 实现中 | ✓ | ✓ | ✓ | – | ✗ | ✗ |
| 待验收 | ✓ | ✓ | ✓ | ✓ | – | ✓ |
| 已完成 | ✗ | ✗ | ✓ | ✗ | ✓ | – |

**设计和实现中永远拖不到 待验收 / 已完成**：那是模型的报告位和人的签核位。模型忘了报告时用
按钮「手动标记完成」，不用拖动。

## 5. 确认面板

**只在动作被触发后才出现**：不预渲染、不常驻、不预选。浮层贴卡片，点外面等于取消，取消则
前一步什么都没发生——不 cancel、不撤队、不回滚。

```
去向：<已定的轨道 | 删除>
附加：☐ 回滚本次执行的改动
      ☐ 同时迁移本会话其它任务
后果：会停止正在跑的 t7；会撤掉 1 条排队；恢复 3 个文件、删除 1 个
[确认] [取消]
```

点「停止」时去向为空，必须先选；拖动时预填目标；删除时预填删除。

## 6. 机制底座（DSH 已有）

| 能力 | 接口 |
|---|---|
| 投递（忙则排队、闲则开跑，FIFO） | `ISession.prompt(content, 'queue')` |
| 打断当前轮（保留队列） | `ISession.cancel()` |
| 撤销一条排队 | `updateQueue(itemId, 'remove')` |
| 投递身份 | `beginSubmission()` → `requestId` |
| 新建会话 | `ctx.sessions.create({ workspaceId \| cwd, agentPreset })` |
| 从完结点 fork | `ctx.sessions.fork({ sessionId, increaseTitle })`（省略 `atSeq` = 最近完成轮次） |
| 会话目录与运行态 | `ctx.sessions.list` → `running` / `displayTitle` |
| 切到会话 | `ctx.uiWorkspace.openSession(id)` |
| 每轮改动文件与对比 | `ctx.workspaceChanges.summary/diff`（进程内，重启即丢） |
| 模型报告 | `defineTool` + `exec.agent.session` 写看板 |

自己写：看板 JSON、`move` 状态机、git 快照与按路径回滚、派单消息包装。

## 7. 分支流程

### F0 捕获
待办底部「+ 新任务」→ 内联输入 → 进待办。空标题不建，同名允许。
**模型不能建平级任务**，产出只是当前任务的步骤。

### F1 待办 → 设计中（首次派单）
确认面板：目标会话（当前/新建/工作区列表）+ 文案预览 + 后果。
后果：打 baseline → `retain` → `beginSubmission` → `prompt(queue)` → 落执行记录 → 锁定会话。
分支：目标忙 → "排队第 N"；新建 → `sessions.create`（仅本轨道）；取消 → 零副作用。

### F2 待办 → 实现中
同 F1，阶段写"实现"，跳过设计。

### F3 设计中：出方案
`report('design_ready')` → 打 end 快照 → 待实现 + 等你批 + 冻结步骤。
分支：轮次结束但没 report → 卡停在设计中，主动作「继续设计」；`blocked` → 原地 + 阻塞；报错 → 红标 + 重试。

### F4 待实现 → 实现中
确认面板固定「投给 A（已锁定）」。分支：会话已归档 → 「新建会话」或「换会话」；忙 → 排队。

### F5 实现中：写完
`report('implemented')` → 打 end 快照 → 待验收 + 等你验。

### F6 待验收 → 已完成
纯状态变更，不投递。误点给 3 秒撤销。

### F7 退回 / 返工
| 从 → 到 | 投递 | 回滚 | 备注 |
|---|---|---|---|
| 待验收 → 设计中 | 是（重新设计） | 可选 | 必填 |
| 待验收 → 实现中 | 是（按备注改） | 否 | 必填 |
| 待验收 → 待实现 | 否 | 否 | 只是暂缓 |
| 已完成 → 待验收/待实现 | 否 | 否 | 重开，不自动跑 |

### F8 停止
弹去向选择器（不预填），确认后：先撤本卡未消费条目 → `cancel()` → 可选回滚 → 落地。
顺序不能反：**先撤条目再 cancel**，否则队列会按 FIFO 抢跑。取消确认 → 不停止。

### F9 重开（fork）
**这条路上没有排队**：新会话天生空闲，投递即执行。

1. 打 WIP 快照；2. cancel 旧会话（其它卡队列不动）；3. 可选回滚（默认开）；4. `fork(A)` → A'
改锁；5. 投递重开文案 → 立即开始。
分支：无已完成轮次 → fork 是空壳，退回「保留原会话」；旧会话还有别的任务 → 提示会造出两个
活跃会话，可选一起迁（默认迁）；无版本控制 → 跳过 3 并在文案里说明。

### F10 会话侧被动变化
运行中 → 动点；报错 → 红标 + 重试；归档 → 灰标、投递类动作禁用；被外部停止 → 对账后主动作变「继续」。

### F11 刷新 / 重启对账
逐条核对执行记录：会话不存在 → `lost`；排队条目已不在 → 退回"已派单未执行"；
`running=false` 但记录 `running` → 标记该轮未完成。

## 8. 界面元素

- **面板**：头部（标题 / 筛选「全部·需要我」/ 新建）、轨道（名称+计数+折叠）、空轨道虚线投放区。
- **卡片**：标题 → 会话徽标（未派单 / A·运行中 / A·排队2 / A·已归档 / A·报错，点击跳会话）→
  标记 → 主动作（hover，只一个）+「⋯」→ 展开区（描述、步骤、执行记录时间线、每条的回滚入口）。
- **版本控制标**：左下角 `有快照` / `本次无快照` / `无版本控制`（可点开初始化确认）。
- **确认面板**：见 §5。
- **拖拽**：抓手 = 卡片头部；只高亮合法目标；松手出面板。
- **头部入口**：右栏按钮加"需要我"数字角标。
