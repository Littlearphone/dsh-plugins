# 任务板 · 交互设计

一条任务从"用户脑子里冒出来"到"实现完成"的全部分支。写代码前以本文为准。

**两条前提，全文都建立在它们上面：**

1. 任务之间可能毫不相关。
2. 轨道不是线性流程：可以跳级、可以来回。

因此：不存在"上一步"这种概念。回滚、迁移、检查点都以**这张卡自己的执行记录**为单位，
不以轨道顺序为单位。

## 1. 概念

| 概念 | 定义 |
|---|---|
| 任务卡 | 一条任务：标题、描述、轨道、标记、锁定会话、执行记录 |
| 轨道 | 待办 / 设计中 / 待实现 / 实现中 / 待验收 / 已完成。**迁移表才是真源** |
| 标记 | 要不要人出手：等你批 / 等你验 / 阻塞 / 已暂停。与轨道正交 |
| 锁定会话 | 首次派单选定，此后只在该会话执行；fork 重开时改锁 |
| 执行记录 | 每次派单一条：`runId, sessionId, 基线快照, 结束快照, requestId/itemId, 结果` |
| 检查点 | 执行记录里的两个快照，不是"阶段"。命名 `t7#3` |

## 2. 版本控制

### 2.1 粒度：一次派单，一个基线

派单前打 `baseline`，本轮结束时打 `end`。回滚的单位是**执行记录**，不是阶段。

- 「撤掉这次」= 选某条执行记录，把它造成的改动撤掉。
- 「撤掉这张卡」= 回到第一条执行记录的 baseline。
- 列表按时间排，标注那次跑出了什么（`design_ready` / `implemented` / `已停止`）。

### 2.2 回滚按路径，不做整树 reset

工作区是共享的，任务之间无关，所以**只能撤这张卡那次执行真正碰过的路径**：

```
baseline..end 的 diff
  修改 / 删除 → 从 baseline 取回
  新增       → 删除
其它任务在这之后动过同一路径 → 冲突：不覆盖，列出来让人决定
```

回滚前先打 WIP 快照，所以永远能再回去。确认条写清："恢复 N 个、删除 M 个新增、冲突 K 个"。

### 2.3 快照方案：影子仓库

```
git --git-dir=$DSH_HOME/task-board/repos/<ws-key>.git --work-tree=<工作区>
```

不碰用户的 `.git`（index、refs、worktree 全不动），对象和 ref 都在 DSH 目录。忽略规则沿用工作区
的 `.gitignore`，另加一份 DSH 管理的 `core.excludesFile` 兜底。每次快照有超时和体积上限，
**超限就放弃这次快照**，卡片标"本次无快照"，不阻塞任务。

### 2.4 没有 git 就不管

检测：`git rev-parse --absolute-git-dir`（派单时做一次）。

| 情形 | 行为 |
|---|---|
| 仓库内 | 快照可用 |
| 不在仓库内 | 本工作区标记「无版本控制」：卡片灰锁、确认面板警告"中断后无法回滚"、不做快照 |
| 没有 git 可执行文件 | 同上 |

- **不询问、不初始化、不复制目录备份。** 往用户目录写 `.git` 是插件不该有的能力。
- 用户自己 `git init` 之后，下次派单检测到即自动启用。
- 插件永远不执行 `git init`、不写 `.gitignore`、不改任何 git 配置。

## 3. 动作：统一成"离开"

拖动、按钮、停止，都是同一件事：**把卡从当前位置挪到另一个位置**。

```
leave(card, target):
  1. 若在运行 → cancel()
  2. 撤掉本卡未消费的派单条目（不动其它卡的）
  3. 可选：回滚某条执行记录
  4. 落地：target 是轨道就改轨道，是"删除"就删卡
```

target 只有三个来源：

| 触发 | target |
|---|---|
| 拖动松手 | 目标轨道 |
| 点「停止」 | 原地（等价于拖回自己） |
| 点「删除」 | 删除 |

所以「停止」和「拖动」效果完全一致，前者只是把 target 定在原地。

### 动作矩阵

| 轨道 | 运行中 | 空闲 |
|---|---|---|
| 待办 | — | 开始设计 · 直接实现 · 编辑 · 删除 |
| 设计中 | 停止 | 继续设计 · 重开 · 删除 |
| 待实现 | — | 开始实现 · 退回设计 · 删除 |
| 实现中 | 停止 | 继续实现 · 重开 · 删除 |
| 待验收 | — | 通过 · 退回设计 · 退回实现 · 删除 |
| 已完成 | — | 重开 · 归档 · 删除 |

- 删除是通用动作，唯一条件是**不在运行中**。运行中删 = 停止 + target 删除。
- 模型到不了「已完成」，也改不了会话、撤不了队列。
- **新建会话只在 待办 / 待实现**。

### 拖动合法性

`✓` = 允许（运行中则隐含先停止）；`✗` = 不响应。

| from \ to | 待办 | 设计中 | 待实现 | 实现中 | 待验收 | 已完成 |
|---|---|---|---|---|---|---|
| 待办 | – | ✓ | ✗ | ✓ | ✗ | ✗ |
| 设计中 | ✓ | – | ✓ | ✓ | ✗ | ✗ |
| 待实现 | ✓ | ✓ | – | ✓ | ✗ | ✗ |
| 实现中 | ✓ | ✓ | ✓ | – | ✗ | ✗ |
| 待验收 | ✓ | ✓ | ✓ | ✓ | – | ✓ |
| 已完成 | ✗ | ✗ | ✓ | ✗ | ✓ | – |

**设计和实现中永远拖不到 待验收 / 已完成**：那是模型的报告位和人的签核位。模型忘了报告时用
按钮「手动标记完成」，不用拖动。

## 4. 确认面板

只有一个面板，target 和参数由触发方式预填：

```
去向：<轨道 | 删除 | 原地>
附加：☐ 回滚本次执行的改动   ☐ 同时迁移本会话其它任务
后果：会停止正在跑的 t7；会撤掉 1 条排队；恢复 3 个文件、删除 1 个（冲突 1）
[确认] [取消]
```

- 拖动：target 预填目标轨道。
- 停止按钮：target = 原地，回滚默认关。
- 重开（fork）：target = 原地 + 换锁，回滚默认开。

## 6. 分支流程

### F0 捕获
待办底部「+ 新任务」→ 内联输入 → 进待办。空标题不建，同名允许。
**模型不能建平级任务**，它的产出只是当前任务的步骤。

### F1 待办 → 设计中（首次派单）
确认面板：目标会话（当前 / 新建 / 工作区列表，带 运行中·排队N·空闲）+ 文案预览 + 后果。
后果：打 baseline → `retain` → `beginSubmission` → `prompt(queue)` → 落执行记录 → 锁定会话。
分支：目标忙显示"排队第 N"；新建走 `sessions.create`（仅本轨道）；取消零副作用。

### F2 待办 → 实现中
同 F1，文案「直接实现」，跳过设计。

### F3 设计中：出方案
`report('design_ready')` → 打 end 快照 → 待实现 + 等你批 + 冻结步骤。
分支：轮次结束但没 report → 已暂停（继续 / 重开 / 删除）；`blocked` → 原地 + 阻塞；报错 → 红标 + 重试。

### F4 待实现 → 实现中
确认面板固定「投给 A（已锁定）」。
分支：会话已归档 → 「新建会话」（本轨道允许）或「换会话」；忙 → 排队。

### F5 实现中：写完
`report('implemented')` → 打 end 快照 → 待验收 + 等你验。

### F6 待验收 → 已完成
纯状态变更，不投递。误点给 3 秒撤销。

### F7 退回 / 返工
| 从 → 到 | 投递 | 回滚 | 备注 |
|---|---|---|---|
| 待验收 → 设计中 | 是（重新设计） | 可选 | 必填 |
| 待验收 → 实现中 | 是（按备注改） | 否 | 必填 |
| 待验收 → 待实现 | 否 | 否 | 只是暂缓 |
| 已完成 → 待验收/待实现 | 否 | 否 | 重开，不自动跑 |

### F8 停止 / 离开
即 `leave()`：运行中先 cancel，撤本卡未消费条目，然后按 target 落地。
顺序不能反：**先撤排队条目再 cancel**，否则队列会按 FIFO 抢跑。

### F9 重开（fork）
**这条路上没有排队。** fork 出新会话，它天生空闲，投递即执行。

1. 打 WIP 快照；
2. cancel 旧会话（其它卡的队列不受影响）；
3. 可选回滚（默认开，目标是最近一条执行记录的 baseline）；
4. `fork(A)` → A'，改锁，执行记录追加 `sessionHistory`；
5. 向 A' 投递重开文案 → **立即开始**。
分支：会话无已完成轮次 → fork 是空壳，退回「保留原会话」；旧会话还有别的任务 → 提示会造出
两个活跃会话，可选一起迁（默认迁）；无版本控制 → 跳过 3，文案说明工作区未回滚。

### F10 会话侧被动变化
运行中 → 动点；报错 → 红标 + 重试；归档 → 灰标、投递类动作禁用；被外部停止 → 对账置已暂停。

### F11 刷新 / 重启对账
逐条核对执行记录：会话不存在 → `lost`；排队条目已不在 → 退回"已派单未执行"；
`running=false` 但记录 `running` → `stalled`。快照从影子仓库读 refs，跨重启可用。

## 7. 界面元素

- **面板**：头部（标题 / 筛选「全部·需要我」/ 新建）、轨道（名称+计数+折叠）、空轨道虚线投放区。
- **卡片**：标题 → 会话徽标（未派单 / A·运行中 / A·排队2 / A·已归档 / A·报错，点击跳会话）→
  标记（等你批/等你验/阻塞/已暂停）→ 主动作（hover，只一个）+「⋯」→ 展开区（描述、步骤、
  执行记录时间线、每条的回滚入口）。
- **版本控制标**：卡片左下角，`有快照` / `本次无快照` / `无版本控制`（灰锁）。
- **确认面板**：见 §4，贴在目标轨道上。
- **拖拽**：抓手 = 卡片头部；只高亮合法目标；松手出确认面板。
- **头部入口**：右栏按钮加"需要我"数字角标。
