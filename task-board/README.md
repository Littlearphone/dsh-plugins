# 任务列表 · `@local/task-board`

按状态分轨道的任务列表。**当前是卡片状态语言的预览原型**：14 张写死的卡覆盖全部运行态与标记，
只存在 React 内存里，刷新即复位；持久化、会话派单与回滚是下一步（设计见 [DESIGN.md](DESIGN.md)）。

## 文件

| 文件 | 行数 | 内容 |
|---|---|---|
| `index.js` | — | Host 半侧（路由、插件记录） |
| `client.js` | 459 | 入口：locale、标签页与顶栏入口、chunk 装载 |
| `client.css.js` | 290 | 两张样式表（guide + 看板） |
| `client.board.data.js` | 315 | 种子数据、轨道配色、纯几何helper |
| `client.board.actions.js` | 193 | 点击行为：跳会话、改轨道、菜单、弹窗 |
| `client.board.js` | 444 | 状态机：轨道、拖拽、新建 |
| `client.board.view.js` | 490 | 视图：状态词汇、图标、卡片 |

后六个是**包内 chunk**，入口用 `require.async` 并行拉取（`Promise.all`），首次打开标签页多几次本地请求，此后常驻。

分工是"状态 / 行为 / 视图 / 数据 / 样式"五层：`client.board.js` 只持有 React state 和拖拽，
点击副作用在 `actions`，纯函数在 `data`，渲染在 `view`。改卡片外观不需要碰状态机。

## 卡片视觉

视觉语言取自 Linear 的设计系统（`awesome-design-md` 的 `linear` 参考）：表面阶梯、1px 发丝线、
单一强调色、最小 12px 字号。

**三段式，每张卡完全同构**——同样的三条带、同样的顺序，任何一张卡都能按同一套坐标读：

| 带 | 内容（恒在） |
|---|---|
| 头 | 类型图标（20px 圆角底 + 14px 图标）· 编号（等宽）·（右侧）状态徽标 |
| 主体 | 标题（14px / 500，≤2 行）· 会话 + 事实计数（`☰ 3` `▤ 6`，0 也显示） |
| 操作 | 主操作（可复合）· 退回（可复合）· 次操作 · 编辑 · 删除 |

没有左缘色条：轨道本身已经说明了列，卡片上再涂一遍是把同一件事说两次。

唯一的颜色通道是**顶缘 2px**：安静的卡是中性线，有状态的卡换成状态色；运行中时顶缘变成来回
滑动的滑块，状态徽标里的两个点在同一水平线上交替呼吸。

| 状态 | 顶缘 | 徽标（含字形） |
|---|---|---|
| 运行中 | 紫，滑块 | 双点交替 运行中 + 秒表 |
| 排队中 | 石板蓝 | ☰ 排队 N |
| 等你回答 | 琥珀 | ◉ 等你回答 |
| 等你批 / 等你验 | 琥珀 | ◉ |
| 阻塞 | 琥珀 | ⊘ 阻塞 |
| 出错 | 红 | △ 出错 |
| 已归档 | 中性 | ▣ 已归档 |
| 空闲 | 中性 | ○ 空闲 |

阻塞归到"等人"一族（琥珀）而不是"失败"一族（红）：出错是机器坏了，阻塞是只有你能拍板；
⊘ 这个字形把它和别的"等人"分开。已归档不标红——归档不是错误，只是会话不在了。

「等你批 / 等你验 / 阻塞」优先于运行态：人工阻塞比"正在跑"更要紧，所以只占一个状态槽。

**有颜色的卡自动浮到轨道顶部**（稳定排序：标记 > 出错/归档 > 运行/等待 > 排队 > 空闲），否则
一条 2px 的顶缘压在安静卡下面等于没有。同等级之内保留手工顺序。

### 交互

**所有动作都是同一种 24px 图标按钮**：同一个底色（`--tb-surface`）、同一条描边、同一个圆角，
主次只靠图标颜色区分（主操作 ink、次操作 muted、删除红）。没有填充按钮，也就没有「这块为什么不一样」。
没有「⋯」折叠，五个图标在 180px 的卡里放得下。文字在 tooltip 与菜单项里，不在按钮上。

**新建任务只有一个入口：待办轨道标题栏里的「+」**——常驻、不用滚动。点开后输入框出现在该轨道
第一张卡的上方，回车创建、Esc 取消。任务总是以"未开始、未绑定"诞生，别的轨道不生长新卡。

**编辑和删除每张卡都有**，固定在操作行最右：它们是任务本身的属性，不随轨道变化。

「退回」和「开始 / 停止」一样是复合按钮：左瓣退到默认阶段（待实现→设计中、待验收→实现中），
右瓣列出其余可退的轨道。执行中的轨道没有「退回」，只有「停止」——停止本身就要求选去向。

**是否复合由动词决定，不由卡片状态决定**：`stop` 一定带去向、`start` 一定带目标，`pass/reopen`
永远不拆。复合按钮两瓣共用同一个底色与描边，一对之内不会一半填充一半描边。

| 点哪里 | 反应 |
|---|---|
| 状态徽标 | 弹详情：原因 + 版本控制状态 + 「打开会话」 |
| 会话名（含"未派单"，图标恒在） | 切到那个会话，并在那边重新打开任务板标签页 |
| 主操作 | 执行；没绑会话时主操作自己弹目标选择 |
| 主操作右瓣 | 开始类：投递给 <会话> / 在新会话执行；运行中：直接落到某条轨道 |
| 退回右瓣 | 退到 设计中 / 实现中 / 待实现 |
| 其余图标 | 改轨道或弹"原型"说明 |
| 卡片 | 可拖；拖完按注意力重新排序 |

**执行轨道只在执行时存在**：设计中 / 实现中 里的卡一定是 running 或排队中。一轮跑完却没上报，
卡退回阶段入口（待办 / 待实现），所以不存在「继续设计」这种动作。

## 怎么看到它

会话头部**右侧**的工具区（`conversation.session.header.utilities`）会出现一个图标按钮：28×28、
图标是三列看板，悬浮提示「任务列表」（`title`/`aria-label`）。它排在最右那个「更多」菜单
（`session-log-download`，默认 order 0）**左边**——本插件取 order -1。

样式刻意对齐产品按钮（primitives `Button size="sm"` 的 outline 变体）：`--dsw-radius-sm` 圆角 +
发丝内描边 `inset 0 0 0 var(--dsh-hairline-width, .5px) var(--dsw-alias-border-l3)`，hover/active
用 `--dsw-alias-interactive-bg-hover/active`。不是 1px 实线边框。

点它打开右侧栏的任务列表标签页。

六条轨道：待办 / 设计中 / 待实现 / 实现中 / 待验收 / 已完成。拖任意卡片：

- 在同一轨道内上下拖 → 改排序，插入位置由指针相对卡片中线的位置决定，拖动时有蓝色插入线；
- 拖到另一条轨道 → 改状态，计数徽标跟着变；
- 轨道为空时有一条虚线投放区，仍然能接收卡片。

## 实现要点

| 关注点 | 做法 |
|---|---|
| 插入位置 | `indexAt(list, clientY)`：数指针越过了多少张卡片的垂直中线 |
| 移动 | `moveTask()` 纯函数，返回新 lanes；同轨道内移动时索引要减一（先移除再插入） |
| 投放 | 轨道容器上 `onDragOver`（必须 `preventDefault` 才允许 drop）+ `onDrop` |
| 视觉 | 全局只用自己的 `.dsh-board-*` 类名 + `--dsw-alias-*` 令牌，不碰产品类名 |
| 入口 | 头部 utilities 座位（已验证可追加，`replaceRisk: none`） |
